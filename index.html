Getting started with Laertes

Laertes runs next to ODIS. A small macro inside ODIS (the bridge) lets this web page read and change control units, so you do everything from one place while ODIS stays open in the background.

1. Install the bridge macros (once)

  1. Copy mcpserver.py and mcpserver_handlers.py from this repository to C:\ProgramData\OE\macros\.
  2. Updating later: replace mcpserver_handlers.py; the bridge reloads it automatically when the file changes, without restarting ODIS. A new mcpserver.py takes effect the next time you start the macro.
  3. Coming from an older version: the macro used to be called mcpserver_test.py. Delete that file and run mcpserver.py instead (only the new one has Stop bridge).

2. Start the bridge in ODIS

  1. Start ODIS and open the diagnostic session as usual (connect the VCI and the car or bench unit).
  2. Open the macros function in ODIS and run mcpserver.py.
  3. The macro keeps running and listens on 127.0.0.1:8765. Leave it running; while it does, ODIS itself cannot be operated, which is why everything is done from this page.
  4. To use ODIS itself again, press Stop bridge in the top bar: the macro ends and ODIS is free. Run mcpserver.py again to continue with Laertes.

3. Start Laertes

  1. Run laertes.exe. It opens this page in your browser (http://127.0.0.1:23031/, or another free port if that one is taken; the console window shows the address).
  2. Check the top bar: ● ODIS bridge green, the loaded vehicle project (🚗) and 🔌 VCI connected. Red “ODIS bridge offline” means the macro is not running — go back to step 2.
  3. Optional switches: -db (database file), -bridge (bridge address), -nobrowser.
  4. Building from source: double-click build.cmd (needs Go); it runs the tests and produces laertes.exe.

4. Using the tabs

Project units
The units of the vehicle (or the ODIS project offline). Select a unit, then: Identification, Coding (edit bytes or use the decoded tables' dropdowns, then Write to unit… — the coding is read back and verified, and the fault memory is read before and after so you see which faults are new or gone, active or passive; units that also code slave units, such as the gateway 19, offer each coding to pick), Adaptation channels (pick a channel, change values, write, verified), Measurement groups (tick several, Show live for values and graphs), Event memory (faults with repair guidance), Full scan of the unit and Clear DTCs. Use Login… first when a write needs elevated access.
For many units at once, the buttons above the list work on the units the list shows (tick responded only for those that answered, untick it for everything in the ODIS project). On a real car start with Quick scan: it asks the gateway once which units are installed and communicating, identifies only those and ticks responded only, so later scans skip the missing units instead of waiting for their timeouts (without a gateway, e.g. on a bench, use Scan all): Scan all reads their identification; Scan all unit DTCs reads their faults and shows, on every press, how many are new (+) or gone (−) since the press before; Full scan writes identification, coding and faults as a log in the layout of a VCDS Auto-Scan, to copy or download for tools that read those logs.
Retrofit mode
Start retrofit… first scans the listed units and keeps that scan. While the retrofit is active (🔧 in the top bar), every change is stored under its name (by default from the VIN) and the faults the units had before are ignored in counts, scans and the coding fault check. Rename it or look at the scan from before at any time; end it when the work is done. In History, pick the retrofit to see all its changes.
Unit database / Trouble codes
The ODIS database without a car: search a part number or variant, see its tables and every trouble code with repair guidance. Each unit also links to its DTC catalog (offline).
Coding
The large coding editor: bit grid, your .lbl labels and any variant's ODX definition (remembered). Opens from a unit's coding (Open in Coding tab, with Back to unit coding), or with New coding for bytes you type in.
History
Every coding and adaptation write with old → new value, unit, variant and result; for coding also each changed byte and bit and, where a coding definition or .lbl labels are known, each setting before → after. Search any text (unit, VIN, value, retrofit name) or pick a retrofit. Stored in the database, so it survives restarts.
JSON viewer
Send any command to the bridge and inspect the raw reply — for troubleshooting.

Tips

  • Writes change the control unit. Every write asks for confirmation and shows exactly what changes.
  • One operation runs at a time: while one runs (shown in the top bar), others are refused. Stop ends long scans and live views after the current unit.
  • ⧉ copies the text, table or fault next to it. 🌐 translates a fault or error text to English with Google Translate — the text is sent to Google only when you press it.
  • ODIS guided fault finding documents appear only after the vehicle is identified and guided fault finding is started in ODIS; the general guidance works without it.
  • Your data (labels, history, remembered choices) is in laertes.db next to laertes.exe.
