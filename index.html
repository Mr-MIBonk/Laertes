Laertes help

Laertes runs next to ODIS. A small macro inside ODIS (the bridge) lets this web page read and change control units, so you do everything from one place while ODIS runs in the background. This page describes every tab, button and option; hover any button in Laertes for a short description too.

Getting started

  1. You need your own licensed ODIS installation — ODIS-E (Engineering, C:\Program Files\OE) or ODIS-S (Service, C:\Program Files\OS) — and, for a car or bench unit, a VCI that ODIS can use.
  2. Connect the VCI to the car or bench unit and switch the ignition on. You do not need to open ODIS.
  3. Run laertes.exe. It opens this page in your browser (http://127.0.0.1:23031/, or another free port if that one is taken; the console window shows the address and a colored log of what Laertes does).
  4. Laertes installs the bridge macros and starts ODIS in the background with the bridge in it (see the next section). The top bar shows each step with a progress bar; a start takes about a minute.
  5. When ● ODIS bridge turns green and the vehicle project (🚗) and VCI (🔌) appear, open Project units and press Quick scan (car) or Scan all (bench).

The ODIS bridge

Bridge macros (installed automatically)
laertes.exe contains mcpserver.py and mcpserver_handlers.py and copies them to C:\ProgramData\OE\macros\ (ODIS-S: C:\ProgramData\OS\macros\) every time it starts, when they are missing or differ, so the bridge always matches this Laertes. A running bridge picks up a new mcpserver_handlers.py at once; a new mcpserver.py takes effect the next time the macro starts. Coming from an older version: the macro used to be called mcpserver_test.py; delete that file.
Starting with your own VCI
When Laertes starts and the bridge is not running, it starts ODIS in the background, without its window, as ODIS's automation web service (OffboardDiagLauncher.exe -configuration …\laertes-webservice.ini), loads the vehicle project by reading the car's VIN and runs mcpserver.py in it. If the car cannot be identified (e.g. a unit on a bench), the project from Settings › ODIS bridge is used; it is filled in from the project ODIS had loaded last time. ▶ Start bridge in the top bar or in Settings starts it by hand; untick Start the bridge when Laertes starts in Settings to start it only by hand.
Offline, with the virtual VCI
For offline coding and the ODIS database without a car: choose the project (e.g. VW37X) in Settings › ODIS bridge and press ▶ Virtual VCI (top bar) or ▶ Bridge + virtual VCI (Settings); tick Start automatically with the virtual VCI to have Laertes always start that way. Laertes registers its own offline VCI — a J2534 device without hardware, Laertes-Offline (Windows asks for administrator rights once) — and lets the background ODIS use it, so ODIS opens the project and runs the bridge with nothing connected. The simulated units report the Simulation VIN from Settings, and every message ODIS sends shows in the VCI CAN panel. Your own VCI choice in ODIS is put back when that ODIS ends.
A unit on a bench (clamp 15 wake-up)
A unit that sleeps without ignition: turn on Settings › Clamp 15 wake-up. ODIS then uses your J2534 VCI through Laertes's VCI DLL, which sends VW's clamp status frame (0x3C0, clamp 15 on) every 100 ms while the bridge runs, so the units wake up and act as if the ignition were on. The top bar shows the VCI as … via Laertes (clamp 15 wake-up); 🔑 Ignition ON/OFF switches the frame on and off while the bridge runs, like turning the key. Tick Load this project directly in Settings to skip the VIN identification that cannot succeed on a bench (about 15 s faster).
ODIS-E or ODIS-S
The E / S selector in the top bar chooses which ODIS installation Laertes drives. ODIS-S runs the guided functions (component protection, immobilizer). Stop the bridge before switching; the choice applies on the next start. ODIS-S shows a disclaimer dialog at startup: click Accept in the ODIS-S window, otherwise the bridge cannot connect.
When ODIS is already open
ODIS cannot run a macro started from outside while it is open with its window. Either open its Macros function and run mcpserver.py there, or close ODIS and press ▶ Start bridge.
Stopping
The macro listens on 127.0.0.1:8765. ■ Stop bridge ends it (asks first); if Laertes started ODIS in the background, that ODIS closes too, so you can open ODIS normally.
Jobs that outlive the page
Long jobs (basic settings, output tests, flashing, guided functions) run inside ODIS. If you reload or reopen the page while one runs, Laertes picks it up again and shows its progress (in its tab, or in a box at the bottom left with Stop).

Top bar

Tabs
Project units, Unit database, Trouble codes, Vehicles, Coding, History, Retrofit, CP, Immobilizer, Settings and Help. VCI CAN is not a tab: it opens the CAN panel on the right, next to any tab. Laertes remembers the last tab.
⏳ Running operation
The operation in progress and how long it has run. Only one operation runs at a time; others are refused until it ends. Stop ends long scans, live views and jobs after the current step.
🔧 Retrofit
Shown while retrofit mode is active, with the retrofit's name.
● Laertes
Green while laertes.exe runs; red “Laertes offline” when it is closed. The page reconnects by itself when it comes back.
● ODIS bridge
Green: connected (hover for how long the start took). Yellow with a timer and progress bar: Laertes is starting ODIS and the bridge, with the current step. Red “ODIS bridge offline”: hover for the reason; ⚠ means the start failed (the message also appears as a notice).
🚗 Project · 🔌 VCI
The vehicle project loaded in ODIS, and the VCI ODIS is set to use with its state. Hover the VCI for clamp 15 / clamp 30 and DoIP details.
🔑 Ignition ON/OFF
Only with the clamp 15 wake-up: switches the wake-up frame on (units awake) and off (units sleep) without a restart. Each start begins with it on.
↻ Restart VCI
Restarts the VCI through ODIS when it stops answering (asks first; the connection drops for a moment).
▶ Start bridge · ▶ Virtual VCI · ■ Stop bridge
Start ODIS in the background with your own VCI, or with the virtual VCI and the project from Settings; stop the bridge. Which ones show depends on whether the bridge runs.
📋 Activity
What Laertes did in this session, newest first: operations with their duration, results, messages and bridge connects and disconnects. The red badge counts errors you have not seen yet; Clear empties the list.
E / S
ODIS-E or ODIS-S, see above.
📄 ODIS logs
The button at the top right opens the engine.log of the selected ODIS in its default viewer, to see what ODIS itself is doing (startup, errors).

Project units

The left side lists the control units of the vehicle project (address, name, state, fault count). The buttons above it work on the units the list currently shows.

Filter · responded only
Show only units whose address or name contains the text. responded only shows only units that answered (identified by ODIS or a Laertes scan, and not failed since); untick it for every unit in the ODIS project.
Reload from ODIS
Asks ODIS again for the units of the loaded project.
Quick scan
Start here on a real car: asks the gateway once which units are installed and communicating, identifies only those and ticks responded only, so later scans skip missing units instead of waiting for their timeouts.
Scan all
Reads the identification of every listed unit (use it without a gateway, e.g. on a bench).
Scan all unit DTCs
Reads the fault memory of every listed unit and shows, on every press, how many faults are new (+) or gone (−) since the press before.
Coding links across units
Reads every unit's coding definition and trouble codes from the ODIS database (about a minute; no car needed) and links each missing-message fault to the coding setting, in any unit, that says whether its partner is fitted — e.g. the cluster's Kessy_04 fehlende Botschaft to Kessy in the central electronics. Faults and coding settings then show these links with the other unit's address; Help lists how many were found.
Full scan
Identification, coding and faults of every listed unit, as a log in the layout of a VCDS Auto-Scan for tools that read those logs: ⧉ copy it, Download .txt or Close.
Start retrofit…
Opens the Retrofit tab to start retrofit mode (see Retrofit).
⧉ Copy list
Copies the unit list as text.

Unit functions

Select a unit in the list. Its heading shows address, name and identification, with open in unit database (its ODX data) and DTC catalog (offline) (every trouble code it can store). Above each result is the path of what you opened; click an earlier part to go back.

Identification
Part numbers, software and hardware versions, serial number and the rest of what the unit reports. The raw ODIS result is under JSON.
Coding
The unit's coding in an editor: type a byte (two hex digits) or change a setting in the decoded tables below — both edit the same coding, and changed bytes are marked. Units that also code slave units (e.g. the gateway 19) offer each coding to pick.
  • Coding definition (ODIS database): the coding decoded with the unit's own ODX data into named settings with dropdowns. When the unit's variant defines none, Decode with a related variant… lists variants of the same family that do; the one you pick is remembered for this variant (with a warning that its layout may not fit) until you press Forget which variant I selected. Under a setting, related trouble codes lists the faults of the unit's variant that name the same part (e.g. Kessy and Kessy_04 Datenbus fehlende Botschaft): coding a part as installed when it is missing raises them, coding it out stops them. The ODIS database does not link the two, so these are matched by name: a hint, not a rule. Known case adds cases reported by VCDS/ODIS users and in VW/Audi bulletins for this unit's address (e.g. trailer, rain/light sensor, Kessy, alarm siren), with the address where the fault shows and a link to the source.
  • Decode with your .lbl labels: Import .lbl… loads a VCDS-style label file for this variant and subsystem and shows each byte/bit with its label.
  • Reset undoes your edits; Open in Coding tab opens the coding in the large bit-grid editor.
  • Write to unit… shows exactly what changes and asks for confirmation, writes the coding and reads it back to verify. With the fault check on (Settings), the fault memory is read before and after, and you see which faults are new or gone, active or passive. Every write is stored in History.
Adaptation channels
Lists the unit's channels (filter by name). Open one for its parameters with current values: pick a new value from the dropdown (when ODX defines the choices) or type it; changed rows are marked, and hovering a name shows its ODX name and current value. Write to unit… confirms, writes, reads back and does the same before/after fault check as coding; Reset undoes changes.
Measurement groups
Tick one or more groups (All / None, filter), then Show live: the values update continuously, with a small graph per numeric value (hover it for min / max / now) and changed values marked. Stop / Start pause and continue, Interval sets the milliseconds between readings, ⧉ copies the current values. The live view pauses when you leave the tab.
Basic settings
Lists the unit's routines. Open one, fill in its start parameters, tick the measurements to read with each status check and press Start basic setting… (asks first). Its status and values update while it runs; Stop ends it. A basic setting can move actuators and relearn values: meet the conditions from the repair information first.
Output tests
Lists the unit's actuators that ODIS can drive (fans, pumps, valves, relays, lamps, motors). Open one, fill in its start parameters if it has any, tick measurements to read along and press Start output test… (asks first): the unit drives the actuator, and its status and values update while it runs; Stop ends it. Next moves a sequential output test (older units step through their actuators one after another) on to the next actuator. Output tests move and switch parts of the car: keep clear and meet the conditions from the repair information first.
Event memory
The stored faults: code, text, active or passive, status bits and environment data. Open a fault for general guidance (repair steps derived from the code) and ODIS guided guidance, which fetches ODIS's guided fault finding document — available only after the vehicle is identified and guided fault finding is started in ODIS. Coding that can affect this names the coding settings whose name matches the fault, and known cases for a fault at this address, such as a gateway "Timeout node … / 69" pointing at installation-list entry 69 (see Coding above). During a retrofit, faults from before it are listed separately and ignored.
Login…
The security access (login) code for writes that need elevated access. It is remembered for the unit and sent with each coding/adaptation write, because ODIS opens a new connection per operation. Leave it empty to clear it.
Full scan
Identification, coding and faults of this unit as a VCDS-style log.
Clear DTCs
Erases the unit's fault memory (asks first).
Dangerous functions
Shown only when you untick Hide dangerous functions in Settings:
  • Component protection (test)… finds the component-protection adaptation channels and coding settings on the unit and opens them in the adaptation editor, for bench testing how a unit behaves while locked. Writing locks the unit; recovery needs an online ODIS/VW SVM session with valid GeKo credentials. Only on a unit you own and can reactivate.
  • ⚠ Flash firmware (experimental)… and ⚠ Load dataset (experimental)… are orange, experimental and untested. Choose a flash container (.frf/.odx) or programming configuration on the ODIS PC (Browse…) or from your browser (Upload…), then Read / validate config (reads only), then Execute (typed confirmation). A progress bar, ODIS's messages, Cancel and Show the log of the last flash (from ODIS's engine.log) follow the job.

Unit database & Trouble codes

Unit database
The ODIS database without a car (the bridge must run, with any project). Type a unit address (0x0001) or a part number / variant (04C906026, GV_ECM10…) and press Find or Enter. Pick a result for its protocol, location, number of trouble codes and its tables; open a table for its rows with identifiers, parameters, units and possible values. Filter the rows and ⧉ copy them.
Trouble codes
Every trouble code a unit or variant can store, from the same search. Search by code or text (e.g. P0122 or throttle); open a code for its level, number and repair guidance. Base data usually has no codes: pick a variant. ⚙ coding marks codes that a coding setting of the same data names (search coding to list them); open one to see which setting.
Rules
The rules behind the coding hints, with counts. Test error code: give a unit address (or pick a project unit) and a fault code such as U112100 or U1121 00 and press Find causes: Laertes looks the code up in that unit's trouble codes in the ODIS database (no car needed) and, for every fault the code stands for, lists the causes — the coding settings that name it, known cases, the unit that sends a missing message, links to other units' coding — and the general guidance. Or type a fault text to see what the rules say about it. Known cases (faults reported by VCDS/ODIS users and in VW/Audi bulletins) and message senders (which unit sends a CAN message such as ESP_21, or the module an SAE "Lost Communication With …" fault names) can be edited, added and deleted; your changes are kept in laertes.db, a changed built-in rule has Reset, and deleted built-ins can be restored. Patterns are case-insensitive regular expressions; addresses are hex, separated by commas. A case can also name its faults by codes: an SAE code (U112100, or U1121 for every fault type) or the VW fault number VCDS lists first (559893). Faults show all three forms (U112100, U1121 00, VCDS 559893), and the code searches take any of them. Once Coding links across units is built, its links are listed too: Hide one that is wrong and it stops showing in the hints.

Vehicles

Which ODIS project a car needs. Laertes reads ODIS's own vehicle tables from the installation chosen with E / S in the top bar — the VIN tables in the vrtvpt plugins (configuration\plugins\…vrtvpt-*.jar, and for ODIS-E also VRT_VPT-Engineering) and the model lists (PRNR-INFO.xml) of the installed projects — so it works without a car and without ODIS running, and is always as current as your ODIS.

By VIN
Type the 17-character VIN and press Find or Enter, or take it from the car connected through the bridge (VIN of the connected car) or from Settings (Simulation VIN). Laertes decodes each part — manufacturer (WMI), model type (positions 7–8), check digit, model year (position 10), plant and serial number — and lists the matching ODIS projects with the model names ODIS shows, the protocol and communication types (the default in bold), and the PR number a project needs, if any (that equipment must be fitted; see the car's data sticker). Below are the models of those projects from their PRNR-INFO lists, with product IDs — only for projects installed in ODIS.
By model and year
Choose the brand and model: a table shows the project for every model year. Choose a year for the project's details and models.
Use
Use (or a project button in the year table) makes that project the vehicle project in Settings › ODIS bridge, which the virtual VCI and a bench start load.
Search all models
Finds any model by name, project or model ID.

Coding

The large coding editor: every byte as a row of bits.

  • Open it from a unit's coding (Open in Coding tab; ← Back to unit coding takes the edited bytes back to write them), or type hex bytes into the empty editor and press Load for editing.
  • Paste part of a VCDS scan (its Address, ASAM Dataset and Coding: lines): each coding found is offered with its unit, and the variant's labels and definition apply.
  • Tick bits, choose bit-field values from dropdowns, and type your own label for any byte or bit — labels are stored for that variant and subsystem. Import .lbl labels loads a VCDS-style label file.
  • Decode with a variant's definition… searches the ODIS database for a variant whose coding definition decodes the bytes; the choice is remembered.
  • Original and new coding each have Copy; Reset undoes edits; New coding starts over. To write to a unit, go back to it under Project units.

History

Every coding and adaptation write, flash, dataset, basic-setting and output-test run with time, unit, variant, old → new value and result; for coding also each changed byte and bit and, where a coding definition or .lbl labels are known, each setting before → after. Stored in laertes.db, so it survives restarts.

  • Search any text (unit, VIN, value, retrofit name), and choose All changes, Outside a retrofit or one retrofit. With a retrofit chosen: Rename…, Scan before the retrofit and Stop retrofit.
  • ✕ deletes one entry; Clear all deletes every entry (asks first). Neither changes the units.

Retrofit

Retrofit mode groups the work of one job, e.g. fitting ACC.

  1. Start retrofit… (here or in Project units): enter a name (by default from the VIN) and tick the units the retrofit covers (All / None). Scan and start scans them and keeps that scan as the state before.
  2. While it is active (🔧 in the top bar), every coding, adaptation, firmware and dataset change to those units is stored under its name, and the faults they had before are ignored in counts, scans and the coding fault check.
  3. The tab lists its changes as they are written; Units changed filters them by unit, the search field by text. Scan before the retrofit rescans the units and keeps that as the state before; Rename… renames it.
  4. Stop retrofit when done. Its changes stay here (pick it from the list) and in History.

CP & Immobilizer (guided functions)

Both tabs run an ODIS guided function (normally with ODIS-S) and relay what ODIS reports. ODIS does the work — it talks to the units and the VW online service and decides the outcome; Laertes shows its messages and lets you answer its dialogs. They need the car connected and the vehicle identified in ODIS.

Vehicle identification (CP tab)
Identify vehicle lets ODIS fill in brand, model, year, variant and engine from the VIN. Where it cannot decide, pick the right choice and press Continue; Start over clears ODIS's selection. This changes only ODIS's vehicle selection, nothing in the car.
Component protection
Press Remove CP… next to a unit in the list (filter it), or type an address (e.g. 5F) and press Remove component protection…. Asks first.
Immobilizer
Lists the immobilizer functions ODIS offers for this vehicle; Run… starts one (asks first). Reload functions asks ODIS again.
While it runs
The right side shows ODIS's messages with times. Dialogs ODIS raises (choices, inputs, the GeKo username and password, the VW online sign-in in your browser) appear there to answer; the GeKo credentials from Settings are filled in. Click a message to highlight that step's CAN messages in the VCI CAN panel. What is ODIS waiting for? shows ODIS's guided-function threads, to see where a run that seems stuck waits. 🌐 translates the messages, ⧉ copies them.
Online services
By default Laertes serves a stand-in for VW's online services on 127.0.0.1:23032 (sign-in and the GSB web service), so the online step of component protection completes offline, e.g. with the virtual VCI. Start laertes.exe -grpstub=false to use VW's real backend.

VCI CAN panel

VCI CAN in the tab bar or ◀ CAN on the right edge opens the CAN trace next to any tab; drag its left edge to change the width, ▶ Hide closes it. It records all the time, also while hidden. Only the virtual VCI (and the clamp 15 wake-up frames) is traced; a real VCI is not.

  • ▶ is ODIS → unit, ◀ is unit → ODIS. Each message is decoded — UDS service, identifiers, values and negative responses with their meaning; hover a message for details.
  • ⏸ Pause stops updating the table (recording continues); Clear empties the trace; the filter shows only messages containing a CAN ID, service, DID or meaning.
  • Setup events adds connects, filters and ioctls; Wake-up frames adds the periodic clamp 15 frames.
  • All / Operations / Coding / Adaptation / CP / Basic setting show only the messages sent while that kind of operation ran.
  • ⧉ Copy copies the shown messages tab-separated, for a spreadsheet or text file.

Settings

Stored in laertes.db, so they apply in every browser and survive restarts.

ODIS bridge
  • Start the bridge when Laertes starts — on by default; works only while ODIS is not open with its window.
  • Start automatically with the virtual VCI — offline mode: no car or interface, control units do not answer.
  • Vehicle project — loaded offline, and online when the car cannot be identified by its VIN. It suggests the projects ODIS has and is filled in from the project ODIS loaded last.
  • Load this project directly, without identifying the car by its VIN (bench) — about 15 s faster on a bench; leave it off for a car, so a different car gets its own project.
  • Simulation VIN — the VIN the simulated units report (DID 0xF190); empty uses the built-in default. Applies on the next start.
  • ▶ Start bridge / ▶ Bridge + virtual VCI — start now.
Clamp 15 wake-up (bench)
  • Send a clamp 15 frame periodically — needs a VCI that ODIS uses as a J2534 device; through a car's OBD port the gateway usually does not pass it on. With the virtual VCI the frames only appear in the CAN trace.
  • CAN ID (hex; up to 7FF is 11-bit; default 3C0, Klemmen_Status_01) and every … ms (default 100).
  • Data — hex bytes, default 00 00 03 00 (byte 2: bit 0 clamp S, bit 1 clamp 15, bit 2 clamp X, bit 3 clamp 50).
  • E2E data ID — default C3: byte 1's low nibble counts 0…15 and byte 0 becomes the AUTOSAR CRC-8. Empty sends the data unchanged (older units).
  • Changes apply on the next bridge start.
After a write
Read the fault memory before and after each coding/adaptation write — turn it off to write faster without the fault check.
Translation
The language 🌐 translates into (English, German, Czech, Slovak, Polish, French, Spanish, Italian, Dutch, Russian, Ukrainian, Turkish, Portuguese, Romanian, Hungarian), and Translate coding and adaptation names and values automatically. Texts go to Google Translate only when you press 🌐, or as they are shown with automatic translation on.
Dangerous functions
Hide the dangerous unit functions (on by default): Flash firmware, Load dataset and Component protection (test).
VW online sign-in
Sign in signs ODIS in to the VW online service (GRP) in your browser now; otherwise it asks when an online function needs it. The GeKo username and password are filled into ODIS's dialog when a guided function asks; Save stores them, the password encrypted for this Windows user.

Tips

  • Writes change the control unit. Every write asks for confirmation and shows exactly what changes.
  • ⧉ copies the text, table, fault or error next to it; in coding and adaptation tables each row has its own ⧉ too.
  • 🌐 next to a fault or error text translates it; 🌐 Translate above a table translates its names and values. A translated text is underlined with dots; hover it for the original. What is written to a unit is never translated.
  • Hover a parameter for help: its ODX name, current value, bit position and possible values.
  • The filter fields above long lists (units, channels, groups, variants, table rows, trouble codes) narrow them as you type.
  • Laertes serves one browser page at a time, because two pages driving ODIS would interfere. Another page shows Single access limit; Use Laertes here takes over.

Troubleshooting

“ODIS bridge offline”
Hover it for the reason. ODIS open with its window: close it, or run the macro from its Macros function. ODIS-S waiting on its disclaimer: accept it in the ODIS-S window. Then press ▶ Start bridge; 📄 ODIS logs shows what ODIS did.
Units do not answer
Check the ignition (or 🔑 Ignition on a bench), press ↻ Restart VCI, then scan again. With the virtual VCI only the simulated units answer.
A write is refused
Use Login… with the unit's login code. The error, and with the virtual VCI the CAN trace, shows the unit's negative response and its meaning.
A guided function seems stuck
Look for an open dialog on the right, press What is ODIS waiting for?, or Stop it in the top bar.
No ODIS guided fault finding
Identify the vehicle in ODIS and start guided fault finding there, then retry; the general guidance works without it.

Files & command-line options

  • laertes.db next to laertes.exe holds your data: settings, labels, history, retrofits and remembered choices.
  • -db <file> — use another database file.
  • -bridge <host:port> — the bridge address (default 127.0.0.1:8765).
  • -nobrowser — do not open the browser.
  • -grpstub=false — use VW's real online services instead of Laertes's stand-in on 127.0.0.1:23032.
  • Building from source: double-click build.cmd (needs Go); it runs the tests and produces laertes.exe.
